# 切册（cheki album）

打开即是一页连续的切奇手帐：最近一场、成员架、场次架和下方的拼布时间线同时可见，
不再用三个 tab 分开浏览。入口：首页「我的切奇」旁的「切册」，或成员详情右上角「切册」按钮
（只显示该成员）。

照片归属仍从 `activity_record_media` 分组，不新增表。自动扫描先校正可信的卡片四边，再用本机人脸关键点判断朝向；批量拍切的复核、识别和保存使用同一份切图，不需要打开人脸识别或修改切册设置。横躺切图可用相纸的签名宽边佐证人脸朝向；如果相纸是竖的、照片里的人却是横的，则要求两个检测尺度都支持同一方向。已经缺边的卡不再向内裁。

拍照、普通导入、批量拍切和已核对 ZIP 入册时在本机生成优化图。打开切册后优先处理在看的照片，再逐张补齐扫描旧图，不用逐张点开。切册、存图记录、切总览、成员详情存图条和统计附件的扫描缩略图读取轻量成品，大图读取同一成品的完整尺寸。备份和「原色」仍使用入册原件。
单张自动扫描和批量拍切共用相纸规格识别：三寸（Instax Mini）按 54×86 mm，五寸（Instax Wide）按 108×86 mm。在看清相纸轮廓后按实际规格校正；单张找不到唯一可信卡片时保留画面和比例。识别结果影响图像和新入册的规格建议，不改已有流水。

旧切图已经缺边、被拉宽时，Android 切册会在入册后和打开图库时，查找同一活动日、已有照片权限可读的相机原拍。它从原拍重新找卡片，用图案与笔迹匹配原附件，把确认是同一张卡的成品用于缩略图和大图。无需选照片或逐张点重扫；原拍反光遮住内容时，如果旧附件仍覆盖几乎整张相纸，只用旧附件的像素按已确认的纸框校正，缺角留空。原拍不在、纸框不清或无法确认同一张时保留入册照片的本地增强视图。手动框选的旧切图也参与匹配；已核对导入的取景不替换。「原色」仍可看入册时的文件。

只有完整照片访问权限才会自动匹配；切册会提示如何补齐权限，部分授权不用于匹配。在原拍池读取不完整或匹配期间发生变动时，本轮不采用结果。原拍引入严重反光时，仅在确认同一张切图且旧附件覆盖校正纸框至少 98% 的情况下，用旧附件像素重投影；否则保留原有显示。给早先流水补拍时，照片保存实际拍摄时间，流水日期不变。

## 照片如何落到 成员 / 日期 / 场次

| 维度 | 规则 | 代码 |
|------|------|------|
| 成员 | 1. `media.owner_person_id` / `owner_person_name`（批量拍切单人时写入）；2. 对应流水是 counter → `counterId` / `personId` / 名字 → 成员卡；3. 多切流水只有 1 位参与者 → 该成员；4. 多切 ≥2 人 → “团切”，照片同时进入每位参与者的同框；5. 门票场次且无 owner → 未归属 | `album_grouping.dart` 的 `_AlbumMemberLookup` |
| 日期 | 有 `captured_at` 用拍摄时间，按活动日 06:00 分界（`activityDayOf`）；否则用流水日期，纯日期流水（00:00）保持当天（`recordActivityDay`）；两者都没有 → “日期不明” | 同上 / `face_recognition_rules.dart` |
| 场次 | 流水日 + 活动名 + 场馆 + 场次标签（`session_label`）共同决定；同日同活动同馆同“第X部”的多条流水合并为一个场次；流水日期/名称都缺失时退回当天 | `_sessionKey` |
| 规格 | 切图取流水计数（`3寸 2`、`团切 · 2张` 等）；纪念照取媒体类型 | `_specLabel` |
| 场次补充 | 演出名单缓存只做补充：日期 + 活动名精确匹配时填充城市/场馆；只有流水没有写“第X部”时才用它填充开演时间，避免把一场的时间安到另一场 | `AlbumEventHint` |

`images.db`（「抽取图片」）没有成员/日期/流水关联，因此不进入切册，避免把无关图片混进来。
人脸样本表（`face_samples`）只用于识别训练，不作为相册归属：一张团切可以有多张脸，样本数不等于这张切属于谁；批量拍切的单人归属会写入 media owner，这里只信 owner 与流水。
隐藏成员的照片仍会进入切册（相册完整性），成员卡片是否显示由首页开关决定。

## 页面结构

- 首页 `album_page.dart`：一页 `CustomScrollView`。
  - 顶部一行统计：张数 · 活动日 · 成员 · 场次（不再有占四分之一屏的大 hero）。
  - 「最近一场」：最新有日期的场次。3 张以上做成带胶带、轻微倾斜的散落拍立得；1–2 张时改用「左图右文」紧凑卡，让成员架保持在首屏内。照片不足时不补假图，只放大真实有的那张。点开 = 该场次页。
  - 「成员」横向架：每位成员一张応援色拍立得小封面、姓名（完整显示，不用首字）和张数，按张数排序；「全部」进入完整成员网格页。
  - 「场次」横向架：奶油门票感 stub 卡，2–3 张竖版照片占主区，右侧撕票区放日期和张数，下方一行标题/成员；「全部」进入完整场次页。场次没有活动名时标题按「成员团体名 → 场馆 → 成员名 → 未记公演」回退（`albumSessionTitle`）。
  - 「时间线」：月份 sticky header；活动日有 3 张以上时第一张放大（大图 + 右侧两张小图，其余按列换行），只有 1–2 张时按普通网格格子显示，避免单张照片占满整屏。每月一个 `SliverVariedExtentList` 懒加载照片行，并给出精确总高度；避免每日独立列表提前创建屏外首行。缩略图按实际宽度 `cacheWidth` 解码；宽比例的扫描卡保留纸边与签名，字幕紧贴照片。右上角日历按钮仍可按年份/“日期不明”跳转（偏移由 `album_timeline_mosaic.dart` 与落地页各段高度精确计算）。
- `album_members_page.dart` / `album_sessions_page.dart`：完整网格/列表页，复用原 `AlbumMembersView` / `AlbumSessionsView`。
- `album_session_page.dart`：单个场次页，头部日期戳 + 成员 chips + 照片网格。
- 拍立得白色/奶油色相框在浅色和深色模式都保持纸感；深色模式只改变页面背景，相框上的文字使用固定的深色印墨。
- 查看器 `album_viewer_page.dart`：`photo_view` 0.15.0（MIT）提供双指缩放、双击缩放、左右滑动；Hero 从点击的拍立得放大；底部信息栏显示成员、日期、场次、规格、切图/纪念照与处理方式。
- 查看器每次打开默认「清晰」，右上角可切回「原色」临时对照。只有在识别到可信且完整的主卡四边时才做透视校正；方向证据不足时保留原方向；减反光只处理有局部证据的区域，无法区分反光、白笔或原照片内容时保留。原色直接查看入册文件。

## 显示设置

切册右上角「显示设置」（滑杆图标）提供以下本机持久化选择：

- 时间线印边：应援印边 / 经典白边（默认）。应援印边把成员色印在照片下方的纸边，团切为多色分段；不覆盖照片或签名。设置中可直接比较印边小样。
- 时间线列数：自动 / 2 / 3 / 4；自动沿用 Dream 的屏宽适配。
- 每天一张主打：关闭后时间线按等大照片排列。
- 时间线照片铺满相框：关闭后显示完整照片，保留签名和边角；全屏查看器始终可看原图。
- 首页展示收藏架：关闭后略过最近一场、成员架和场次架，直接翻时间线。

点「保存显示设置」后生效；退出弹层不保存。设置只影响切册首页和成员时间线，
不改变成员/场次归属、原图、流水、首页计数器布局或独立成员/场次列表。
默认全部保留原 Dream 展示。修改布局后回到切册顶部，年份跳转使用新布局的精确高度。

## 已核对切图附到已有流水

全局切册右上角「切册操作 → 导入已核对切图」支持本地 ZIP，成员私册不提供入口。
先预览流水/日期/卡名/团体与照片数量，确认只附图、不补记账；重复跳过，目标或归属冲突则阻止整包导入。
包格式和限制见 [导入已核对切图](CHECKED_CHEKI_IMPORT.md)。

## 依赖与许可

- 新增：`photo_view: 0.15.0`（MIT，bluefireteam，纯 Dart，无 native 代码；仅依赖 flutter）。已 pin 版本。
- 未新增 `flutter_staggered_grid_view`：拍立得统一比例，内置 `SliverGrid` 已足够且天然懒加载；masonry 需要先算所有高度，反而不适合大量照片。
- 内建 `InteractiveViewer` / `PageView` 也被评估过，但没有 `photo_view` 的双击/惯性缩放细节。若合并时想完全去掉依赖，`album_viewer_page.dart` 是唯一使用点，可替换成 `InteractiveViewer + PageView`。
