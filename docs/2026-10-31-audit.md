## 发现并修复的问题

### 性能

1. **首页不再全量读取 activity_records**
   - 首页之前和统计页一样 `getActivityRecords()` 全表加载；3k 条记录 86ms，
     50k 条会明显变成启动负担。
   - 新增 `getHomeActivityRecords()`：只取 `record_type='multi'` 或
     `custom_cheki_counts_json` 非空的记录，供多人切去重和自定义切奇类型聚合；
     另用 `getActivityRecordCount()` 取总数。
   - 同一份 60 卡 / 3000 条记录探针：全量 86ms → 首页支持记录 4ms。
   - 字幕的“N 条记录”仍显示全量总数，不影响语义。

2. **启动首帧前做重维护**
   - 原 `_loadCounters(reconcileImportedRecords: true)` 在首帧前 `await`
     OTA 记录同步、主题色回填，再查 counters/records。
   - 现在先查库、先渲染；维护放到 `addPostFrameCallback`，完成后再静默刷新。
   - 影响：冷启动首屏不再被大库的 identity/theme 扫描阻塞。

3. **概览统计每次 build 重复计算**
   - `_overviewTotal` / `_overviewTypeTotals` 每次 getter 都遍历所有 multi 记录，
     并且每条记录都会重建一次可见 counter 列表。
   - 现在 `_HomeOverviewSnapshot` 缓存 `memberTotal / overviewTotal / byType`，
     仅在 counters、records、hidden scope 或排序变化时失效。
   - 复杂度从“每次 build O(records × counters)”降为“缓存失效时一次”。

4. **数据库索引**
   - 新增 `idx_counters_person_id`、`idx_counters_name_group`、
     `idx_activity_records_counter_id`、`idx_activity_records_person_id`、
     `idx_activity_records_type`。
   - 现有 `occurred_at DESC`、`source+source_record_id` 唯一索引保留。

5. **3 列卡片文字换行**
   - `PopupMenuButton` 的默认 48px 触控区挤占了紧凑卡片的姓名宽度。
   - 改为自定义 `child` + `InkWell`，保留可点区域但把布局宽度降到 22px。

6. **同步快照构建**
   - 60 张卡 / 3000 条记录实测（debug、本机 macOS）：
     - `getCounters` 2ms
     - `getActivityRecords` 86ms，`getHomeActivityRecords` 4ms
     - `SyncService.buildSnapshot` 79ms，JSON 约 2.73MB
   - 这是 debug 数据，不代表 release 真机；但说明 3k 条记录下快照可接受。
   - 已避免对每张卡重复 `firstWhere` 找 custom totals。

### 门票 2.0（第三轮）

1. **票种 + 免费/付费**
   - `activity_records` 新增 `ticket_type` / `ticket_is_free`（schema v20）。
   - 新增 `ticket_types` / `ticket_price_presets` 表和 `TicketPricingService`；
     `免费票`、`预售票`、`现场票`、`学生票`、`女性票`、`特典票`、`VIP票` 默认票种。
2. **自动价格**
   - 优先使用演出名单文案解析出的 `isFree` / `ticketTiers`（预售/现场/VIP 等）；
   - 没有文案票价时，保存门票按 `event+venue+ticket_type` 记忆价格；下次同场次/票种
     自动带入；再没有历史价格时使用票种默认价。第一次使用某票种时会把默认价从 0
     学习成实际价。
   - 免费开关会强制单价 0；统计区分免费/付费张数。
3. **UI**
   - 首页新增 LIVE TICKETS 票根卡（缺口/虚线/免费付费/票种/金额）；
   - 门票页可选择票种、免费场次、自动价格；新增“门票价格”管理页；
   - 统计页新增免费/付费/门票金额/票种明细，流水显示票种和免费标记。
4. **演出名单票价（第三轮新增）**
   - MineCool 的 `events_detail.json` 没有独立票价字段，但 `description` /
     `retweeted_text_raw` 文案中经常有 `🎫门票 一般：¥25`、`预售/59 现场/69`、
     `无料入场` 等信息。
   - 新增 `extract_ticket_info()` 解析免费入场和常见票种；过滤抽奖、积分兑换、
     日期等噪声；生成 `isFree` / `ticketTiers` 写入 JSON。
   - 偶像库 schema v4 增加 `is_free` / `ticket_tiers_json`；演出名单页显示票价，
     门票录入选中场次时自动带入票价。
   - 当前抓取覆盖率是**文案可用时约 41/76 条 detail 场次**有票价/免费信息；
     其余场次保持手填/历史学习，不伪造价格。
   - **线上 feed 仍未更新**（已检查 `idol_activity_events.json` 无 `ticketTiers` /
     `isFree`）；需要重新部署 `tool/deploy_idol_activity_updater.sh` 才会生效。
5. **同步**
   - MCP `add_ticket` 支持 `ticket_type` / `is_free`；snapshot summary 和
     `get_overview` 增加门票统计；app 执行操作后同样记忆价格。
6. **测试**
   - `ticket_pricing_test` 覆盖默认票种、场次价格学习、免费/付费统计、票种 CRUD、
     dialogs/draft round-trip。

### 计数与名单维护（第二轮）

1. **计数漂移：旧版多人切无字段**
   - 旧数据可能有 `multi_cut_quantity` 但没有 `multiCountField` 的多人切记录；
     这种记录从未写入成员计数，但首页总览仍会按参与人数减重复贡献，导致总数被少算。
   - 首页总览和 MCP snapshot 现在都跳过 field 为空的 legacy multi；新增回归测试
     `legacy multi quantity without a count field does not undercount`。

2. **偶像成员维护：改一个团籍会改名共享真人**
   - 旧 `upsertMember` 把旧 `personId` 原样传入 `_ensurePerson(preferredId:)`，
     用户把某团籍的“真人主档名”从 A 改成 B 时，会把所有共享 A 的团籍/计数一起改名。
   - 现在按新名字查找/创建真人，不再改旧主档；清空“真人主档名”会真正解绑
     （新增 `unlinkPerson`），不会动已有计数。
   - 新增 `test/idol_member_identity_test.dart`。

3. **演出名单维护：静默清空、坏数据、排序和离线**
   - 空 bundle 原会清空本地缓存；现在抛错并保留缓存。
   - 单条坏日期/坏 JSON 原会让整批同步失败或让 picker 崩溃；现在逐条跳过。
   - 非 http(s) 地址现在拒绝；`synced_at` 在未来时不再被误判为“新鲜”。
   - 场次改为“离今天最近优先”，而不是 30 天前的最旧场次排第一。
   - picker 远端同步失败时回退本地缓存并提示；之前会直接报错、看不到缓存。
   - 新增“演出名单”页（偶像数据库右上角日历图标），可查看来源/同步时间、搜索、
     手动同步最新场次。

### 功能 / 正确性

1. **Release APK 的 INTERNET 权限**
   - `android/app/src/main/AndroidManifest.xml` 原先没有显式声明，靠插件合并
     才拿到；现已显式加入，避免未来插件变化导致更新/同步不可用。
   - 主线已允许 cleartext，局域网 HTTP 可用。

2. **macOS 无法发起网络请求**
   - Debug/Release entitlements 只有 `network.server`，没有 `network.client`；
     已补上，桌面端同步/更新可用。

3. **iOS 局域网 HTTP**
   - 增加 `NSAllowsLocalNetworking` 和 `NSLocalNetworkUsageDescription`，
     不开放任意 HTTP，只允许本地网络；跨公网仍应使用 HTTPS。

4. **首页缺少状态**
   - 新增首次加载骨架、空状态（含“显示已隐藏成员”分支）、下拉刷新。
   - 加载失败仍用 SnackBar，不阻塞页面。

5. **菜单/弹层可发现性**
   - 排序合并为一个菜单（方向 + 数量/名称/颜色，带 check）。
   - 更多菜单加入“MCP 同步”。

6. **测试辅助函数重名**
   - `buildHomeBreakdownEntries` 原来同时存在于 `main.dart` 与
     `widgets/counter_card.dart`，重构后会造成 ambiguous import。
   - 已从 `main.dart` 删除，统一由 `counter_card.dart` 导出。

7. **同步桥接缺失**
   - 原先没有机器可读接口；新增 `mcp_server`（stdio + HTTP + SSE + REST）和
     App 端 `SyncService` / `MCP 同步` 页面。
   - 采用“App 快照上行 + AI 操作队列下行”的本地优先模型，App 始终是最终数据源。

## 剩余风险 / 下一轮建议

1. **全量记录加载**：首页已改为只取多人切/自定义切奇支持记录；统计页和最近记录
   仍会全表加载。3k 条可接受；5–10 万条时应考虑分页/聚合表/增量查询。
   演出名单页目前一次取 1000 条，足够近期窗口但还不是无限分页。
2. **启动 identity reconcile**：已挪到首帧后，但大库仍可能产生一次后台扫描；
   可加“数据版本号 / 上次维护时间”跳过无变化启动。
3. **同步冲突**：MCP 只做增量排队，不做双向 tombstone/字段级合并；如果 App 与 AI
   同时对同一成员做修改，以 App 本地状态为准，AI 操作在 App 拉取时套用。
4. **MCP 不能删除/编辑已有记录**：故意保守；需要时可在 App 内操作，或后续加
   `edit_record`/`delete_record` 并做审计日志。
5. **Token 存储**：App 用 SharedPreferences 明文、server 用本地文件；仅适合可信
   设备/局域网。公网部署请用 HTTPS + 短期 token。
6. **God widget 仍在**：`main.dart`、`chart_page.dart` 仍然巨大；本轮只做 UI 层
   和启动路径优化，没有冒险拆架构。
7. **Web**：项目有 `web/`，但 sqflite 不支持 Web；同步页在 Web 会明确报错。
8. **测试并行**：见上，建议统一 `--concurrency=1`。
9. **真实服务器部署**：Docker/systemd 已实测，但尚未在你确认的情况下写入 bgvps；
   `tool/deploy_mcp_server.sh --dry-run` 已就绪。
